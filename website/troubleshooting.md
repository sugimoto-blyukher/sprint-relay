# トラブルシューティング

## Discord コマンドが見えない・実行できない

設定ギルド、Bot の起動状態、applications.commands スコープ、チャンネル権限、ユーザー ID の対応を確認してください。会議とタスクのコマンドはそれぞれ設定済みのチャンネルから実行します。詳細は [外部サービス連携](../docs/integrations.md) と [Discord 操作ガイド](../docs/discord.md) を参照してください。

## 仕様が生成されない

/spec show で会議の状態、/relay jobs と /relay status でジョブとプロバイダーを確認します。外部 AI が有効か、参加者の同意が対象プロバイダーに与えられているかを確認します。すべての AI が停止している場合でもタスク操作と予測は継続できます。手動運用は[会議・仕様・タスク発行](../docs/workflow.md)を参照してください。

## 承認できない

現在の digest、査読の記録、整合性検証の状態、承認者権限を確認します。修正版の digest には新しい検証が必要です。未解決の指摘を受け入れる場合は通常の承認と異なる明示的な理由が必要です。検証や公開確認を回避しないでください。

## Issue が発行されない

製品リポジトリの公開状態、書き込み権限、保存済み計画、発行ジョブを確認します。公開リポジトリへの発行には別の公開確認が必要です。通信エラーで発行途中になった場合、同じ承認済み版の計画を使って復旧します。詳細は[公開確認と復旧](../docs/workflow.md)を参照してください。

## AI が停止・degraded になった

/relay status、/relay jobs、運営者の doctor を確認し、認証・利用制限・Worker の稼働・合成 Probe の状態を調べます。利用制限を回避する操作は行わないでください。Codex の Worker と実環境の受け入れについては[導入・復旧](../docs/deployment.md)を参照してください。

## 更新後に障害が発生した

すべての書き込みを停止して状態・ログを保全し、[導入・復旧ガイド](../docs/deployment.md)のバックアップおよびロールバックの手順に従います。SQLite の復元だけで既に GitHub に発行された Issue やコメントは取り消されない点に注意してください。
