# Account-authenticated agents

Use fictional project data for commissioning. Approve the vendor, data-use settings and account entitlement before enabling a provider. Limit this service to the named team. The provider configuration starts unverified. A successful authenticated tool submission is the evidence that inference and the MCP connection work. CLI availability, a process exit, or an HTTP response alone cannot supply that evidence.

## Muse

Review the operator's obligations before offering a connector through Muse. Meta's Connector Terms cover MCP servers and require submission for review before making a connector available. Check the applicable terms and approval process for the intended deployment. Review data retention, memories, permitted project data and participant consent. [Connector Terms](https://platform.muse.ai/terms) · [Connector settings](https://www.meta.com/en-gb/help/superintelligence/1687253048996149/)

Configure the remote MCP endpoint behind HTTPS and the project's OAuth provider. In the target Muse account, use the supported connector settings to authorize that endpoint with the management scope. Register the matching client, subject, audience and issuer in SprintRelay. On a synthetic project, set `enabled` and `terms_confirmed` while leaving `verified` and `schedule_confirmed` false. Ask Muse to call `get_project_context`, reverse its synthetic challenge and submit it in the `probe_answer` argument to the same tool. Observe the receipt in `/relay status`. After verification, check that a real fixture claim succeeds and that separate project IDs, approval and technical-audit operations are denied. If this account cannot authorize this custom MCP connector, leave Muse unverified. [MCP authorization](https://modelcontextprotocol.io/specification/latest/basic/authorization)

Give Muse the management instructions below. Ask it to run the patrol every 45 minutes, then observe at least two unattended commissioning challenge receipts in `/relay status`. Check the actual interval, and test a missed or expired slot on the synthetic project. Review per-action consent prompts in the connector settings. Set `schedule_confirmed` only after observing the scheduled behavior. Update Muse's own recurring task when changing the interval. This implementation environment had no authorized Muse account or live scheduled task. [Scheduled tasks](https://www.meta.com/en-gb/help/superintelligence/1484325780075655/) · [Management prompt](management.md)

## Codex

Use the official native Linux binary with a dedicated, licensed ChatGPT account login. Run the vendor's login command under the dedicated worker UID. Check `codex login status`, `codex exec --help`, and `codex features list`. Record the exact release. The worker forces account login, read-only mode, a clean config, and disabled shell and external connector features. Configure the optional model only when the account supports it. This workspace reported `codex-cli 0.172.0-alpha.2` and the required help and feature flags. Account inference and an isolated MCP submission for this release remain unverified. ## Claude Code

Keep disabled unless the deployment's agreement permits this use. Anthropic's legal guidance limits intermediation of end users' usage. A personal subscription shared behind a team service does not establish entitlement. Obtain confirmation for the actual service/operator arrangement. Install the unmodified native client. ## Antigravity

This optional audit adapter requires a native `agy`, a dedicated Google account with authorized unattended use, and a private Secret Service instance containing only that account. Use its official account login with the dedicated bus. Expose only that service using a filtered Unix socket at `/var/lib/sprintrelay-antigravity/keyring/bus`, private to the worker UID. Grant the filter access only to `org.freedesktop.secrets`; a desktop or shared session bus exposes unrelated services and is unsuitable. Confirm no project uses pay-as-you-go or automatic credit overage. On the pinned release check `agy --help` for print mode, output format, default mode and sandbox. The gateway installs job-specific settings denying commands, file writes and URL actions. An assigned audit may read the fixed evidence file. Other outside-workspace paths require approval or are explicitly denied. The only eager MCP server is SprintRelay. During commissioning test that a scripted request to use a banned tool is denied. This environment did not have the executable, keyring or account. Leave disabled if these controls cannot be verified. ## Linux worker deployment

1. Install SprintRelay and dependencies into a root-owned virtual environment at `/opt/sprintrelay/.venv`. Run Core as user/group `sprintrelay`. Create one unprivileged system account per installed CLI, named `sprintrelay-codex`, `sprintrelay-claude_code`, or `sprintrelay-antigravity`. Each home is `/var/lib/<username>`, mode 0700. Give these accounts separate private groups. Keep the Core state directory, runtime secrets, configuration and repository checkouts inaccessible to all worker UIDs.
2. Install a recent unprivileged bubblewrap supporting `--disable-userns`. For each provider install its native executable as `/opt/sprintrelay-workers/<provider>/agent`. Save the exact stdout of that binary's `--version` to the sibling `version` file. Root owns all image files and directories. Stage only any required dynamic loader and shared libraries under the image's `lib`, `lib64` or `usr/lib` at their expected relative paths. Do this from trusted distribution/vendor packages. Scripts, SCM clients, checkout files, shells, additional executables, plugins and vendor launchers needing Node are unsuitable for this minimal image.
3. Sign in using only the official client under that provider's UID and approved account. Codex's dedicated `.codex/auth.json` and Claude's `.claude/.credentials.json` require mode 0600 and private parent directories. They are mounted as opaque, read-only files into a disposable session. Login renewal that requires writing them is done outside the worker with the official CLI. Antigravity uses the dedicated Secrets-only socket described above. The app never opens the account files.
4. Configure a loopback HTTP CONNECT proxy on port 3128 for official vendor TLS endpoints needed by these specific clients. Allowlist the provider domains required for the authorized clients and reject general forwarding. The host must enforce cgroup IP filters on the worker systemd units. Verify direct external connections from the worker cgroup are denied and the proxy allows only those vendor endpoints. Loopback hosts the private MCP port and the proxy. Isolate unrelated privileged local services on the deployment host.
5. Install the two worker template units and enable only the configured provider sockets, for example `systemctl enable --now sprintrelay-worker@codex.socket`. The gateway accepts job metadata only from the Core UID on the root-created socket. New process groups and disposable mount/PID namespaces run each pinned CLI. The limit is one invocation per provider for either role. Core additionally reserves the provider across active leases. A timeout, Core disconnect or gateway shutdown terminates the worker. No raw CLI stdout or stderr is published.
6. Check that the namespace can start inside your LXC configuration. Confirm an approved synthetic probe receives its bound job lease, solves the challenge, and returns its MCP receipt. Try an expired token, a different job, a different project and a disallowed action; each must fail. Use fictional source markers to verify only the immutable, bounded audit context is visible. Record binary version, permitted data, terms and test time. For commissioning, set `enabled` and `terms_confirmed` and leave `verified=false`. The Watchdog dispatches a synthetic probe; confirm the account-specific proof in `/relay status`. Set `verified=true` only after the expected proof, terms and isolation checks. Repeat on every CLI update. If namespaces, egress enforcement, account isolation or provider capabilities fail, keep that candidate disabled and retain manual service.

For PR and CI audits, Core checks the active lease and consent, filters the pinned GitHub diff, and passes up to eight bounded text fragments. The gateway mounts the resulting SHA-tagged JSON at `/evidence/context.json` from a sealed anonymous in-memory file, mode 0400, for the actual invocation. Repository paths are labels within JSON. Full files, private account data and a checkout are outside this mount. Secret patterns trigger line redaction; the approved provider still receives private project context. The same evidence is available through `get_audit_context`; specification audits use the authorized MCP path. Repository commands, tests, hooks, code changes, commits and pushes cannot be requested through the gateway. The optional isolated execution of project tests is outside this deployment. A synthetic host test of bubblewrap in the implementation environment hit a kernel permission denial. Verify the actual Linux/systemd/LXC namespace before deploying.
