## GitHub

Use a private management repository for the approved specifications and task ledger. Configure the exact product repositories that may receive issues. Give the management credential Contents write on the private management repository. Use a separately scoped product credential for Contents read, Issues write, Pull requests write when posting evidence-backed review comments, Actions read and required metadata access. Limit each installation or fine-grained PAT to its respective repositories. The product credential must have no Contents write permission. Prefer credentials restricted to the intended resource owner and repositories. Branch rules must permit the service to update its ledger in the management repository. Runtime credentials and PR CI credentials are separate. [Repository contents](https://docs.github.com/en/rest/repos/contents#create-or-update-file-contents) · [Issues](https://docs.github.com/en/rest/issues/issues#create-an-issue) · [Workflow runs](https://docs.github.com/en/rest/actions/workflow-runs#list-workflow-runs-for-a-repository)

For a GitHub Project, create the board and roadmap views and copy the Project v2 node ID into `github.project_id`. Give the deployment identity write access to that Project. Configure a single-select `Status` with Todo, In Progress, In Review, Blocked, Done and Cancelled. Add date fields named `Start date` and `Target date` to display forecast dates on the roadmap. Projects fields have day-level precision. The Discord Gantt provides the intraday view. With an empty project ID the service operates through issues, the ledger and Discord. A Project synchronization failure queues a notice and leaves the issue available. [GitHub Projects API](https://docs.github.com/en/issues/planning-and-tracking-with-projects/automating-your-project/using-the-api-to-manage-projects)

## Discord

Create an application and bot in the Developer Portal, install it in the configured guild and supply its bot token through `DISCORD_TOKEN`. Use the `bot` and `applications.commands` scopes. Set the guild, member and channel IDs in the TOML configuration. Grant the bot View Channel, Send Messages, Attach Files and Read Message History in the selected channels. Team members need Use Application Commands. Set privacy overrides on the meetings channel before importing any transcripts. After running the service, check `/task list` and use the message context menu on a synthetic transcript. During a Discord outage, mapped GitHub users can queue authorized issue-comment commands for the poller. [Discord application commands](https://docs.discord.com/developers/interactions/application-commands) · [Discord operator guide](discord.md)

## Agent integrations

SprintRelay exposes authenticated, project-scoped MCP tools. The agent supplies its own official client session. CLI stdout can contain diagnostics; a validated, authorized MCP result completes each job. Keep human review and approval in Discord.

- **Muse personal agent.** In the owner's account, register the authenticated HTTPS connector and trigger one synthetic meeting by hand. For the periodic check, configure a 45-minute schedule in Muse, confirm an authenticated claim/read/completion on that schedule and inspect the checkpoint after a missed run. Confirm the account's supported interval, approval prompts and timeout behavior before declaring the integration verified. Keep Muse unavailable if the connector cannot satisfy the server's authorization requirements. [Meta connectors](https://www.meta.com/en-gb/help/superintelligence/1687253048996149/) · [Meta scheduled tasks](https://www.meta.com/en-gb/help/superintelligence/1484325780075655/) · [Connector terms](https://platform.muse.ai/terms)
- **Codex CLI.** The account owner signs in using the official client in the dedicated run environment. Check the installed version and `codex exec --help`, then run the scoped synthetic MCP submission. Use it as the primary technical auditor and eligible emergency management fallback. [Noninteractive Codex](https://developers.openai.com/codex/noninteractive) · [Codex authentication](https://developers.openai.com/codex/auth) · [Codex MCP](https://developers.openai.com/codex/mcp)
- **Claude Code.** Management fallback requires explicit confirmation that the account's terms permit this deployment. Keep it disabled while entitlement or noninteractive operation is unclear. The intended owner signs in with the official CLI; test the installed `claude -p` mode and MCP integration in the isolated environment. [Claude Code headless mode](https://code.claude.com/docs/en/headless) · [Claude Code MCP](https://code.claude.com/docs/en/mcp) · [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
- **Antigravity.** Optional audit fallback. Verify account entitlement, the installed `agy -p` interface and bounded read-only audit in isolation before enabling it. [Headless use](https://antigravity.google/docs/cli/headless/) · [MCP](https://antigravity.google/docs/cli/mcp/) · [Installation and authentication](https://antigravity.google/docs/cli/install/)

Participants authorize each external destination by name, including alternatives, at meeting import. Review provider retention, learning settings and terms before granting consent. Do not transfer provider login tokens to SprintRelay. When all eligible agents are unavailable, preserve pending work and use the manual review/import operations. Task actions, GitHub synchronization and deterministic forecasts continue.
