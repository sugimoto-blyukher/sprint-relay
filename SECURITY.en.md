# Security Policy

[日本語](SECURITY.md) | **English**

## 1. Supported Versions

Currently, security fixes for Sprint Relay target the latest implementation on the main branch.

Continued security maintenance and backports for previous versions are not guaranteed.

## 2. Reporting a Vulnerability

If you discover a security vulnerability, please report it privately using GitHub's [Private vulnerability reporting](https://github.com/sugimoto-blyukher/sprint-relay/security/advisories/new).

Please avoid disclosing exploitable details of unresolved vulnerabilities in public issues, pull requests, or discussions.

Reports should include the following information where applicable:

- A description of the vulnerability
- Affected versions or commits
- Execution environment
- Steps to reproduce
- Potential impact
- Proposed fixes, if any

Do not include actual credentials, third-party personal information, or private meeting records in vulnerability reports.

Security testing must be conducted in environments you control or for which you have explicit authorization.

## 3. Security Model

Sprint Relay emphasizes the protection of human decision-making, confidential information, credentials, and access permissions to external services.

Its design is guided by the following principles:

- Principle of least privilege
- Separation of authority between humans, management AI, and audit AI
- Isolation of Core and Worker execution environments
- Authentication, authorization, and input validation
- Human authority over significant decisions and approvals
- Explicit consent for data sharing with external services
- Fail-closed behavior when required security prerequisites are not satisfied

Outputs and decisions generated by AI must not be trusted unconditionally.

For details regarding security mechanisms, authentication methods, and permission boundaries, refer to the [current specification](sprint-relay-v2-specification.md).

## 4. Developer and Operator Responsibilities

### Developer Responsibilities

Sprint Relay developers aim to:

- Provide security-conscious default configurations.
- Implement appropriate security mechanisms and permission boundaries.
- Document official deployment procedures and operational prerequisites.
- Verify security-critical functionality.
- Investigate reported vulnerabilities and provide fixes where appropriate.

### Operator Responsibilities

Sprint Relay operators are responsible for:

- Proper maintenance of operating systems, dependencies, and external services.
- Protection of credentials and access tokens.
- Appropriate access controls for files, directories, and networks.
- Maintaining execution environment isolation.
- Management of data and backups.
- Reviewing the terms of use and data handling policies of external services.
- Obtaining the necessary consent before sharing data with external services.

For supported execution environments and deployment prerequisites, refer to the [deployment guide](docs/deployment.md).

Security is not guaranteed for configurations that deviate from the official deployment procedures, disabled security mechanisms, independent modifications, or improper operational practices.

## 5. Vulnerability Handling and Disclosure

Reported vulnerabilities will be assessed for reproducibility, scope, and severity, and addressed where appropriate.

The project prioritizes coordination with reporters regarding the timing and content of vulnerability disclosures.

The project does not guarantee specific response times, remediation deadlines, or monetary rewards. Nor does it guarantee the absence of all vulnerabilities or security across every possible deployment environment.
